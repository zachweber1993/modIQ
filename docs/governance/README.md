# Governance (Project Tracking & Process)

This folder holds project tracking and process documents — where things currently stand, and how the engineering workflow operates. It is distinct from **architectural governance**, which lives at `docs/engineering/GOVERNANCE.md` (the Governance Register, Crate Boundary Rules, and Documentation Authority order). See `docs/DOCUMENTATION_MAP.md` for the full distinction if this split is unfamiliar.

---

## Contents

- **`PROJECT_STATUS.md`** — the authoritative, current repository dashboard: active Sprint, Documentation Release, Engineering Release, Governance Register summary, and the Product & Interaction Design Track.
- **`CHANGELOG.md`** — repository history, Documentation Release and Sprint by Sprint.
- **`RepositorySynchronizationPolicy.md`** — how approved artifacts (from either lineage) enter the repository, and the Repository Synchronization / Repository Evolution classification governing what may be prepared directly versus what requires prior Product Owner approval.
- **`ROADMAP.md`** — long-term development phases. Stale as of this writing (last updated 2026-07-16); see `docs/DOCUMENTATION_MAP.md`'s Known Navigation Gaps.
- **`EngineeringGuide.md`** — the canonical engineering workflow description (see also `docs/engineering/PROJECT_HANDOFF_v1.0.md`, Section 5, for the authoritative version).
- **`CodeReviewChecklist.md`** — code review checklist.
- **`DocumentationRelease.md`** — Documentation Release history and status.
- **`templates/`** — reusable document templates (e.g., Implementation Report).
